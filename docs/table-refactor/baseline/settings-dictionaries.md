# Baseline: Settings/Dictionaries/Index.vue

Зафиксировано: 2026-08-14, тенант studio2 (studio2.localhost:8000/settings/dictionaries).

Скриншоты: `screenshots/settings-dictionaries-makes.jpg`, `-models.jpg`, `-service-categories.jpg`, `-client-roles.jpg`.

## Структура (важно, отличается от других страниц)
Одна страница, левое меню (12+ пунктов, сгруппированных по разделам: Транспорт/Каталог и номенклатура/CRM и клиенты/Заказ-наряды/Инструменты) переключает `activeTab` — **чисто клиентское состояние** (`@click="activeTab = item.key"`), БЕЗ навигации/перезагрузки страницы. Все данные для ВСЕХ вкладок приходят в одном Inertia-пропсе при первой загрузке. В разметке — **6 разных `<table>`**, каждая обёрнута в `<div v-show="activeTab === '...'">` — то есть все 6 таблиц физически в DOM одновременно, показывается одна через CSS (не `v-if`, значит скрытые таблицы тоже рендерятся Vue). НЕТ пагинации, НЕТ чекбоксов, НЕТ `DataTableToolbar` ни у одной из 6 — только заголовок+кнопка «Добавить...» в шапке каждой карточки.

## 6 таблиц:
1. **Марки автомобилей** (`activeTab === 'makes'`) — простая: Марка/Кол-во моделей/Статус/Действия. 1 строка (Audi, 1 шт., Активно).
2. **Модели автомобилей** (`activeTab === 'models'`) — вложенный `v-for` (марка → её модели через `<template v-for="make">` + `<tr v-for="model in make.models">`): Марка/Модель/Тип кузова/Категория-Класс/Статус/Действия. 1 строка (Audi/Q5/Седан/1/Активно).
3. **Категории услуг** (`activeTab === 'service_categories'`) — Название/Направление бизнеса (бейдж `ri-node-tree` или серое «Общая категория»)/Действия. 4 строки (Полировка/Химчистка/Оклейка плёнкой — Детейлинг; Мойка авто — Автомойка).
4. **Категории товаров** (`activeTab === 'product_categories'`) — простейшая: Название/Действия (всего 2 колонки).
5. **Универсальные справочники** (`activeTab` ∈ ключам `lookupTypes`, кроме `work_order_status`) — ОДИН общий блок обслуживает МНОГО разных lookup-типов (Источники клиентов, Роли клиентов, Типы кузова, Классы автомобилей и т.д. — все переключаются одной и той же таблицей, просто с другим `activeTab`/`lookups[activeTab]`): Значение (+ 🔒 иконка и title, если `is_system`)/[Цвет — ТОЛЬКО если `activeTab === 'client_role'`]/Статус/Действия (2 иконки ИЛИ серый текст «Системная», если `is_system`). Есть доп. инфо-плашка над таблицей про влияние на ценообразование (`pricingImpactFor`), вне `<table>`. Пример живых данных — Роли клиентов: Клиент/Подрядчик/Поставщик, ВСЕ системные (замок + «Системная» вместо действий, цветной бейдж-значение в колонке «Цвет»).
6. **⚠️ ИСКЛЮЧЕНА ИЗ МИГРАЦИИ: Статусы заказ-нарядов** (`activeTab === 'work_order_status'`) — `<draggable tag="tbody" v-model="workOrderStatusesList" handle=".status-drag-handle" @end="onStatusesReordered">`, тот же паттерн и та же несовместимость с `DataTable.vue`, что у `Settings/Posts` (см. `settings-posts.md`). Доп. колонка «Порядок» (drag-handle) слева. Не трогать в этом пакете.

(Раздел «Инструменты» → «Импорт марок/моделей» — форма загрузки CSV, не таблица, вне скоупа. «Операционные прайсы» в левом меню — внешние ссылки на другие страницы, не часть этой страницы.)

## Консоль на момент фиксации
Без ошибок.

## На что смотреть после рефакторинга
- Мигрировать блоки 1-5 (Марки/Модели/Категории услуг/Категории товаров/Универсальные справочники), блок 6 (Статусы заказ-нарядов) — оставить как есть.
- Каждый `v-show="activeTab === '...'"` блок оборачивает СВОЙ `<DataTable>` — 5 отдельных экземпляров компонента на странице, не переиспользование одного.
- Блок 2 (Модели) — вложенный `v-for` (по маркам, затем по моделям марки) должен превратиться в плоский массив строк ДО передачи в `:rows` (DataTable не поддерживает вложенный source, только плоский `rows` — нужен `computed`, который делает `flatMap` по `makes`, добавляя `make` в каждую строку модели).
- Блок 5 (Универсальные справочники) — условная колонка «Цвет» (`v-if="activeTab === 'client_role'"`) должна отражаться и в списке колонок (`:columns`), и в теле — колонки для DataTable нужно вычислять computed'ом в зависимости от `activeTab`, а не жёстко задавать статичным массивом.
- Иконка 🔒 (`is_system`) и замена колонки «Действия» на серый текст «Системная» — сохранить условие `v-if="!lookup.is_system"` внутри слота `#actions`.
- Инфо-плашка про ценообразование (`pricingImpactFor`) — вне `<table>`, не трогается.

## Результат после миграции на DataTable.vue (2026-08-14)
Мигрированы 5 из 6 таблиц (Марки, Модели, Категории услуг, Категории товаров, Универсальные справочники) — блок «Статусы заказ-нарядов» оставлен без изменений (draggable tbody, см. выше).

Сверено в браузере (LinuxChrome) после рефакторинга — все 4 проверенных вживую вкладки визуально идентичны baseline:
- **Марки** — Audi/1 шт./Активно, без изменений.
- **Модели** — flatMap корректно развернул вложенные `makes[].models[]` в плоский список (Audi/Q5/Седан/1/Активно); клик по «Редактировать» открыл модалку с ПРАВИЛЬНО предзаполненной маркой «Audi» — подтверждает, что `model.make.id` (объект марки внутри развёрнутой строки) корректно заменил старый параметр из внешнего `v-for`.
- **Категории услуг** — 4 строки с бейджами направлений (Детейлинг/Автомойка), без изменений.
- **Роли клиентов** (динамическая колонка «Цвет», активна только для `client_role`) — все 3 системные роли с замком и «Системная» вместо действий, бейдж цвета в отдельной колонке.
- **Источники клиентов** (тот же блок 5, но БЕЗ колонки «Цвет») — переключение `activeTab` корректно убрало колонку «Цвет» из `lookupColumns` (computed), остались только Значение/Статус/Действия — подтверждает, что зависящий от `activeTab` набор колонок пересчитывается верно при переключении вкладки.

Ни одной ошибки в консоли на всех проверенных вкладках. Тесты бэкенда 25/25. Регресс не обнаружен.
