# Baseline: Settings/Channels/Index.vue

Зафиксировано: 2026-08-14, тенант studio2 (studio2.localhost:8000/settings/channels).

Скриншот: `screenshots/settings-channels.jpg`

## Структура
- «Настройки компании», вкладка «Каналы связи».
- Header-карточка с кнопкой «Добавить канал» прямо в шапке (НЕ `DataTableToolbar` — нет поиска/фильтров вообще).
- НЕТ чекбокс-колонки. `channels` — простой массив (не paginated object), без `<Pagination>`.
- Колонки — статичные.
- Строк на момент фиксации: 0 («Каналы ещё не подключены...»).

## Колонки
1. Название — полужирный + опционально номер телефона серым под ним
2. Тип — текст (WhatsApp/Telegram/MAX/SMS)
3. Провайдер — текст (Wappi.Pro/SMS Aero)
4. Локация — текст (или «Все локации»)
5. Статус — условно ОДИН из двух вариантов: если мессенджер и нет `external_profile_id` → красный бейдж «Ошибка настройки»; иначе — обычный бейдж по `statusClasses`/`statusLabels` (pending/connected/disconnected — warning/success/danger)
6. Действия — ДО 4 кнопок, первые два взаимоисключающие (`v-if`/`v-else-if`): «Повторить» (если ошибка настройки, с анимацией `animate-spin` пока `retryingId === channel.id`) ИЛИ «Подключить» (QR, если мессенджер и не подключён) — затем всегда «Редактировать»/«Удалить»

## Консоль на момент фиксации
Без ошибок.

## На что смотреть после рефакторинга
- НЕТ `selectable` (нет чекбоксов вообще на этой странице).
- Условная логика статуса и условная логика первой кнопки действий (retry/QR) — сохранить `v-if`/`v-else-if` внутри слотов как есть.
- Анимация `animate-spin` на кнопке retry, пока идёт запрос — не потерять `:disabled` состояние.

Сверено в браузере (LinuxChrome) после рефакторинга: визуально идентично baseline-скриншоту (пустое состояние, шапка без чекбоксов/пагинации), ни одной ошибки в консоли. Регресс не обнаружен.
