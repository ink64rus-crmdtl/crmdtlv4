# Baseline: Operations/Appointments/Index.vue — «Вид: Список»

Зафиксировано: 2026-08-14, тенант studio2 (studio2.localhost:8000/operations/appointments), переключатель «Список»/«Календарь» в положении «Список».

Скриншот: `screenshots/operations-appointments-list-after.jpg` (пустое состояние — записей у тенанта не было; в отличие от остальных 3 страниц пакета, live-скриншот ДО правки кода не снимался — структура зафиксирована чтением исходника, сверка визуальной идентичности сделана только по колонкам/бейджам самого кода, не по пиксельному сравнению).

## Структура
- Страница «Операции», вкладка «Записи». Переключатель «Список ⇄ Календарь» + тумблер «Просмотр по умолчанию» над таблицей — вне `<table>`.
- Тулбар: поиск («Поиск по комментарию...») + «Фильтры» + «Настроить столбцы» (кнопка «Новая запись» — отдельно, в шапке переключателя видов, не в тулбаре таблицы).
- Чекбокс-колонка: да. Колонки — динамические (`activeColumns`).
- Строк на момент фиксации: 0 («Записи не найдены.»).

## Колонки
1. чекбокс
2. Время записи (`start_at`) — начало полужирным + « — HH:MM» окончания серым
3. Клиент — имя + телефон серым под ним (или «—»)
4. Автомобиль — марка+модель+[госномер] (или «—»)
5. Локация — текст (или «—»)
6. Мастер (`employee`) — ФИО сотрудника ИЛИ фиолетовый бейдж «Подрядчик» + имя клиента-подрядчика ИЛИ серое «Не назначен»
7. Статус — **интерактивный `<StatusBadgeSelect>`** прямо в ячейке (не текст!): опции — полный список `appointmentStatuses`, если запись уже `converted` (заблокирован), иначе `selectableStatuses` (без `converted`); `@update:model-value` сразу шлёт PATCH через `changeStatus()`
8. Комментарий — текст (или «—»)
9. Действия — до 4 состояний: зелёная иконка «конвертировать в заказ-наряд» (`isConvertible`) ИЛИ зелёная «перейти к заказ-наряду» (если уже есть `work_order_id`) — взаимоисключающе; затем всегда «Редактировать» (задизейблена, если `status === 'converted'`) и «Удалить» (задизейблена, если `converted` и НЕ админ, с разными title в зависимости от роли)

## Консоль на момент фиксации
Без ошибок.

## На что смотреть после рефакторинга
- Ячейка «Статус» — `<StatusBadgeSelect>` внутри `#cell-status`, должна продолжать реально менять статус через API, не просто визуально.
- Колонка «Действия» — 4 условных варианта первой кнопки/двух дизейбл-состояний вторых двух — все ветки `v-if`/`v-else-if`/`:disabled` перенести без потери логики.
- Переключатель «Список ⇄ Календарь» и календарное представление (FullCalendar) — полностью вне `<table>`, при переключении на «Календарь» DataTable вообще не рендерится (весь блок под `v-else`/`<template>`).

Сверено в браузере (LinuxChrome) после рефакторинга: пустое состояние отрендерилось со всеми 8 заголовками колонок корректно (Время записи/Клиент/Автомобиль/Локация/Мастер/Статус/Комментарий/Действия). Для полноценной проверки интерактивных элементов создана живая тестовая запись через UI (Иванов Сергей Вячеславович, МДТЛ, 17.08.2026 10:00–11:00): в таблице корректно отобразились клиент+телефон, локация, «Не назначен» (мастер), зелёная иконка конвертации (запись ещё не отменена/не пришла), карандаш и корзина. Интерактивный `StatusBadgeSelect` в ячейке статуса проверен вживую — клик открыл выпадающий список опций (Запланирована/Подтверждена/Не пришёл/Отменена), выбор «Подтверждена» реально обновил статус через API (кнопка сменила текст на «Подтверждена», без перезагрузки страницы). Тестовая запись затем удалена через иконку корзины, таблица вернулась в пустое состояние. Ни одной ошибки в консоли на всех шагах. Регресс не обнаружен.
